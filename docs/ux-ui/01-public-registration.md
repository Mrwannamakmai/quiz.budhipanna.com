# Workflow: หน้าสมัครสอบธรรมศึกษา (Public Registration Form)

**Route:** `/` (ไม่ต้อง login)
**ไฟล์หลัก:** `src/app/page.tsx`, `src/app/registration-form.tsx`, `src/app/actions.ts`, `src/lib/registration.ts`

## 1. วัตถุประสงค์

ให้บุคคลทั่วไปกรอกใบสมัครสอบธรรมศึกษาออนไลน์ ระบบตรวจสอบความถูกต้องของข้อมูล + กันสมัครซ้ำด้วยเลขบัตรประชาชน แล้วบันทึกลง Google Sheets โดยอัตโนมัติ

## 4. รายละเอียดแต่ละขั้นตอน (Step-by-step)

### ขั้นตอนที่ 1 — ข้อมูลผู้สมัคร (`step === 0`)

| ฟิลด์ | ชนิด input | บังคับ | Validation |
|---|---|---|---|
| ปีการศึกษา (พ.ศ.) | text (numeric) | ✅ | ห้ามว่าง (ค่าเริ่มต้น = ปีปัจจุบัน+543) |
| คำนำหน้าชื่อ | select | ✅ | เด็กชาย/เด็กหญิง/นาย/นาง/นางสาว |
| ชื่อ / นามสกุล | text | ✅ | ห้ามว่าง |
| เลขประจำตัวประชาชน | text (auto-format `X-XXXX-XXXXX-XX-X`) | ✅ | ต้องเป็นเลข 13 หลักเท่านั้น (ตัวกรอง non-digit อัตโนมัติ) |
| อายุ (ปี) | number | ✅ | 1–120 |
| วันเกิด/เดือนเกิด/ปีเกิด (พ.ศ.) | number/select/number | ✅ | ตรวจวันที่ถูกต้องจริงตามเดือน+ปี (รวม leap year) |
| เบอร์โทรศัพท์ | tel | ✅ | รูปแบบ `0XXXXXXXXX` (9–10 หลัก) |
| LINE ID | text | ❌ | ไม่บังคับ |

**UX detail:** เลขบัตรประชาชนจะถูก mask แสดงเป็น `X-XXXX-XXXXX-XX-X` แบบ real-time ขณะพิมพ์ (ฟังก์ชัน `formatCitizenId`)

### ขั้นตอนที่ 2 — ที่อยู่และการศึกษา (`step === 1`)

ใช้ dataset ที่อยู่ไทยในเครื่อง (`src/data/thai-addresses.json`, ~1800 records จากโปรเจกต์ `thai-address-database`)

- **Cascading dropdown**: จังหวัด → อำเภอ/เขต → ตำบล/แขวง → รหัสไปรษณีย์
  - เปลี่ยนจังหวัด → รีเซ็ต อำเภอ/ตำบล/รหัสไปรษณีย์ทั้งหมด
  - เปลี่ยนอำเภอ → รีเซ็ต ตำบล/รหัสไปรษณีย์
  - เลือกตำบลแล้ว ถ้าตำบลนั้นมีรหัสไปรษณีย์เดียว → **เติมอัตโนมัติ**; ถ้ามีหลายรหัส → ให้ผู้ใช้เลือกเอง
  - Dropdown ระดับล่าง (อำเภอ/ตำบล/รหัสไปรษณีย์) จะถูก **disable** จนกว่าจะเลือกระดับบนก่อน พร้อม placeholder บอกให้เลือกลำดับก่อน (เช่น "เลือกจังหวัดก่อน")
- ระดับการศึกษาปัจจุบัน: dropdown ค่าคงที่ (ป.๔–ป.๖, ม.๑–ม.๖, ปริญญาตรี, ประชาชนทั่วไป)
- Validation: บ้านเลขที่/ตำบล/อำเภอ/จังหวัด/รหัสไปรษณีย์ (5 หลัก) ต้องกรอกครบ

### ขั้นตอนที่ 3 — ประวัติธรรมศึกษาเดิม (`step === 2`)

- Checkbox "เคยสอบได้ธรรมศึกษามาก่อน" (`hasPreviousCert`) เป็น **ตัวควบคุมหลัก**:
  - **ไม่ติ๊ก** → ฟอร์มย่อยซ่อนทั้งหมด, ค่า `targetLevel` ของขั้นตอนที่ 4 ถูกรีเซ็ตเป็น `"ตรี"` บังคับ
  - **ติ๊ก** → แสดงฟอร์มย่อย (ชั้นเดิมที่สอบได้ [บังคับ], ช่วงชั้นเดิม, เลขที่ประกาศนียบัตรเดิม, ปีที่สอบได้, จังหวัดที่สอบได้เดิม)
  - เมื่อเลือก "ชั้นเดิมที่สอบได้" ระบบจะ **auto-suggest** ชั้นที่สมัครขั้นตอนต่อไป: ตรี→โท, โท→เอก (เขียนในฟังก์ชัน `updateField` จุด `prevLevel`)

### ขั้นตอนที่ 4 — ชั้นสอบและสำนักเรียน (`step === 3`)

- **ชั้นธรรมศึกษาที่สมัคร** (`targetLevel`: ตรี/โท/เอก) — ถูก auto-suggest จากขั้นตอนก่อน แต่ยังแก้ไขเองได้ โดยมีกฎ validation เข้มงวด:
  - สมัครครั้งแรก (ไม่มีประวัติเดิม) → สมัครได้แค่ชั้น **ตรี** เท่านั้น
  - สมัครชั้น **โท** → ต้องมีประวัติเคยสอบได้ชั้น **ตรี** มาก่อน
  - สมัครชั้น **เอก** → ต้องมีประวัติเคยสอบได้ชั้น **โท** มาก่อน
- **สำนักเรียน/โรงเรียน** (`officeName`, บังคับ) + ที่อยู่สำนักเรียนแบบ cascading เหมือนขั้นตอน 2 แต่มี UX พิเศษ: **ค่า default = ใช้ตามที่อยู่ผู้สมัคร** — placeholder ของ dropdown แสดงค่าที่อยู่ของผู้สมัครไว้เป็น hint (เช่น "ใช้ตามที่อยู่ผู้สมัคร (บางนา)") ผู้ใช้จะกรอกเองก็ได้เฉพาะเมื่อสำนักเรียนอยู่คนละที่
- **ช่องทางที่ได้รู้จัก** (`referralSources[]`) — checkbox แบบเลือกได้หลายรายการ (เว็บไซต์ / เพจวัด / เพื่อนแนะนำ / กูเกิล / เฟซบุ๊ก / ยูทูป / ป้ายโฆษณา / ทวิตเตอร์ / Discord / อื่นๆ) ถ้าเลือก "อื่นๆ" จะมีช่อง text input เพิ่มขึ้นมาให้ระบุ

## 5. การนำทางระหว่างขั้นตอน (Step navigation)

- **Progress bar + step indicator** ด้านบนแสดงตำแหน่งปัจจุบันเสมอ พร้อม label แต่ละขั้น
- ขั้นตอนที่ **ผ่านมาแล้ว** (`step < current`) จะกลายเป็นปุ่มคลิกได้ (มีไอคอน ✓) ให้ย้อนกลับไปแก้ไขได้ทันทีโดยไม่ต้องกด "ย้อนกลับ" ไล่ทีละขั้น
- ขั้นตอนที่ **ยังไม่ถึง** ไม่สามารถคลิกข้ามไปได้ (ต้องกด "ถัดไป" ตามลำดับ)
- ปุ่ม **"ถัดไป"** จะ validate เฉพาะฟิลด์ของขั้นตอนปัจจุบันก่อนเท่านั้น — ถ้าไม่ผ่านจะไม่เปลี่ยนขั้นตอน และแสดง error ใต้ฟิลด์ที่ผิด (ใช้ component `<Field error=...>`)
- ปุ่ม **"ย้อนกลับ"** ปรากฏตั้งแต่ขั้นตอนที่ 2 เป็นต้นไป ไม่ validate ใดๆ (ย้อนกลับได้เสมอ)
- ขั้นตอนสุดท้ายจะมีการ์ด **"ตรวจทานก่อนส่ง"** สรุปข้อมูลสำคัญ (ชื่อ, ชั้น+ระดับ+ปีการศึกษา, เลขบัตร masked แสดงเฉพาะ 4 หลักท้าย, เบอร์โทร/LINE) ก่อนให้กดปุ่มสุดท้าย "ยืนยันและส่งใบสมัคร"
- ระหว่างส่งข้อมูล (pending state จาก `useTransition`) ปุ่มจะเปลี่ยนข้อความเป็น "กำลังตรวจสอบและบันทึกใบสมัคร…" และ disable ปุ่มย้อนกลับ/ส่ง เพื่อกันกดซ้ำ (double submit)

## 6. การจัดการข้อผิดพลาด (Error handling)

| ประเภท | ที่มา | การแสดงผล |
|---|---|---|
| Validation รายฟิลด์ (client) | `validateStep()` ใน component | ข้อความสีแดงใต้ input แต่ละช่อง |
| Validation รายฟิลด์ (server, double-check) | `submitDhammaRegistration` ใน `actions.ts` | กลับมาแสดงเหมือนกันผ่าน `result.errors` |
| สมัครซ้ำด้วยเลขบัตรเดียวกัน | `findRegistrationByCitizenId` | แบนเนอร์ error พร้อมรหัสอ้างอิงเดิม + สถานะเดิม |
| ปิด/ไม่อยู่ในช่วงรับสมัคร | `checkRegistrationPeriod` | แบนเนอร์เต็มหน้าแทนฟอร์ม (ซ่อนฟอร์มไปเลย) หรือ error message ถ้าผ่าน period มาแล้วระหว่างกรอก |
| เขียน Google Sheets ล้มเหลว | exception จาก Sheets API | ข้อความทั่วไป "บันทึกใบสมัครไม่สำเร็จ กรุณาตรวจสอบการเชื่อมต่อ..." |
| โครงสร้างข้อมูลผิดรูป (type mismatch) | `isDhammaRegistrationData` type guard | "ข้อมูลแบบฟอร์มไม่ถูกต้อง กรุณาลองใหม่อีกครั้ง" |

ทุกข้อความแสดงผลใน `<div role="status" aria-live="polite">` เพื่อ accessibility (screen reader อ่านทันทีที่ผลลัพธ์เปลี่ยน)

## 7. สถานะ "ปิดรับสมัคร" (Period closed states)

หน้าแรกมี 3 โหมดช่วงเวลา (กำหนดจากหน้า QR Code settings โดยเจ้าหน้าที่):

1. **`force_closed`** → ปิดเสมอ ไม่สนวันที่ → แบนเนอร์ "ปิดรับสมัครชั่วคราว"
2. **`force_open`** → เปิดเสมอ ไม่สนวันที่
3. **`auto`** (ค่าเริ่มต้น) → เทียบวันที่ปัจจุบันกับ `startDate`/`endDate`:
   - ก่อนเริ่ม → "ยังไม่เปิดรับสมัคร — เปิดรับสมัครวันที่ {วันที่ไทย}"
   - เลยกำหนด → "หมดเวลารับสมัครแล้ว"
   - อยู่ในช่วง → แสดงฟอร์ม + แบนเนอร์แจ้ง "เปิดรับสมัครถึง {วันที่}"

## 8. ผลลัพธ์สุดท้าย (Success state)

เมื่อส่งสำเร็จ:
- แสดงข้อความ "ส่งใบสมัครเรียบร้อยแล้ว" พร้อม **รหัสอ้างอิง** รูปแบบ `REG-YYYYMMDD-XXXXXXXX` (สุ่ม 8 ตัวอักษร)
- ฟอร์มทั้งหมดถูก **รีเซ็ตกลับเป็นค่าว่าง** และกลับไปขั้นตอนที่ 1 ทันที (ผู้สมัครคนต่อไปใช้เครื่องเดียวกันกรอกต่อได้)
- **ไม่มีหน้า "ขอบคุณ" แยก** หรือการส่งอีเมล/SMS ยืนยันให้ผู้สมัคร — ผู้สมัครต้องจดรหัสอ้างอิงเองจากข้อความที่ปรากฎ

## 9. Component เสริม: ตรวจสอบการเชื่อมต่อ (`connection-check.tsx`)

Component `ConnectionCheck` (ไม่ได้ถูกเรียกใช้ในหน้า `/` ปัจจุบัน — มีไว้สำหรับ debug/dev) มีปุ่มทดสอบว่า service account เชื่อมต่อ Google Sheets ได้หรือไม่ โดยไม่อ่าน/เขียนข้อมูลจริง เพียงเช็ค `spreadsheets.get` เพื่อยืนยันสิทธิ์
